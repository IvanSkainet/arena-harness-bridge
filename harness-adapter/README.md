# Адаптер DeepSeek Harness для Arena

Bridge запускает один дочерний процесс на привязанный разговор и держит его стандартные потоки открытыми. Профиль `project` создаёт сессию DSH с заданным рабочим каталогом. В ней работают scoped registry, native executor, working directory, FS observation policy, approval service и filesystem skill provider из исходного дерева DSH. Модель отвечает в веб-чате Arena. Ключ модельного провайдера для адаптера не требуется.

## Установка на Windows

Проверено с Node.js 24.21.0, npm, Git и pnpm 11.25.0. Каталоги `harness-adapter` и `deepseek-harness` располагаются рядом. Из их родительского каталога выполните первый блок для получения исходников, если их ещё нет.

```powershell
git clone --filter=blob:none --no-checkout https://github.com/deepseek-ai/deepseek-harness.git deepseek-harness
git -C deepseek-harness checkout --detach 2e39e70496aa02986ca6a820c5d497e816b69d7e
```

Установите зависимости из закреплённых lock-файлов. При повторной установке в Windows сначала завершите процессы адаптера из этого каталога, поскольку декодер PNG удерживает свою DLL. Фильтры pnpm включают зависимости и peer-зависимости исходных пакетов DSH.

```powershell
Push-Location deepseek-harness
pnpm --config.manage-package-manager-versions=false `
  --filter '@deepseek-ai/dsh-tool-fs...' --filter '@deepseek-ai/dsh-fs-local...' `
  --filter '@deepseek-ai/dsh-fs-observation-policy...' --filter '@deepseek-ai/dsh-tool-skill...' `
  --filter '@deepseek-ai/dsh-skill-filesystem...' --filter '@deepseek-ai/dsh-tool-executor-native...' `
  --filter '@deepseek-ai/dsh-working-directory...' --filter '@deepseek-ai/dsh-user-approval...' `
  --filter '@deepseek-ai/dsh-agent-loop...' --filter '@deepseek-ai/dsh-session-projection...' `
  install --ignore-scripts --frozen-lockfile
Pop-Location
Push-Location harness-adapter
npm ci --ignore-scripts --no-audit --no-fund
npm test
Pop-Location
```

Команда, которую запускает Bridge (пример для существующего тестового проекта):

```powershell
node .\harness-adapter\server.mjs --root 'C:\путь\к\проекту' --profile project
```

Программа проверяет ревизию соседнего checkout и ждёт сообщения MCP по stdio. `--root` должен быть абсолютным путём к существующему каталогу. Сервер и его зависимости устанавливаются из доверенных локальных исходников.

## Профиль проекта

- `read` читает текст из рабочей папки через DSH. Профиль проверяет как исходный путь, так и цель после разрешения символических ссылок и junction. Пользователь выдаёт разрешение на чтение каталога, когда привязывает проект.
- `read_image` с параметром `file_path` читает сохранённый в рабочей папке статический PNG. Например, оператор может положить туда снимок приложения и указать его имя в чате. Инструмент использует файловый провайдер и исполнитель DSH, проверяет целостность блоков и декодирует изображение с ограничением в 16 777 216 пикселей. Размер файла ограничен 4 МиБ. Bridge получает исходные байты в блоке MCP `{type:"image",mimeType:"image/png",data:"<base64>"}` и может прикрепить их к ответу в том же разговоре.
- `edit` выполняет буквальную замену штатным инструментом DSH. Терминал показывает путь, объём замены, исходный и новый текст. Для каждого вызова требуется отдельное подтверждение. DSH проверяет, что файл уже читали в этой сессии и его версия соответствует прочитанной.
- `project_test` с параметрами `{}` запускает Node test runner в корне проекта. Терминал показывает рабочую папку и полный массив аргументов. Профиль использует закреплённую команду текущего Node с флагами `--permission --allow-fs-read=<root> --test-isolation=none --test`, подаёт минимальное окружение, собирает stdout/stderr и сообщает неуспешный выход. Лимит процесса — 120 секунд, лимит вывода — 256 КиБ на поток. Запуск исполняет тестовый код проекта с правами, доступными этому процессу Node. Node Permission Model предназначена для доверенного кода. Для прототипа используйте контролируемые тестовые проекты.
- `skill` загружает инструкцию из проектных `.dsh/skills` и `.agents/skills`. Источником тела и сведений о ресурсах служит DSH. В модельный каталог входят имя и описание скиллов с разрешённым вызовом моделью. Для явного выбора пользователем действует признак `user-invocable`. Правки и тесты из загруженных инструкций проходят через те же разрешения.

## Протокол Bridge

Один JSON-RPC 2.0 объект на строку UTF-8. В запросе `initialize` Bridge передаёт стандартные параметры MCP и `_meta.arenaOperatorToken`, случайный секрет минимум из 32 символов. Bridge создаёт его отдельно для каждого процесса и хранит в памяти. Сервер принимает единственную инициализацию, хранит хеш секрета и сравнивает его при каждой операторской команде. Не передавайте в чат метаданные оператора.

| Метод | Параметры | Результат |
|---|---|---|
| `tools/list` | `{}` | `{tools:[{name,description,inputSchema}]}` из реестра профиля |
| `tools/call` | `{name,arguments,_meta:{arenaCallId}}` | Блок MCP `content[0].text`, содержащий JSON снимка операции |
| `arena/status` | `{id}` | Текущий снимок операции |
| `arena/catalog` | `{}` | `{skills:[{name,description}],complete}` |
| `arena/explicitSkill` | `{token,name}` | `{content}`, строка для текущей пользовательской реплики или `null` |
| `arena/decide` | `{token,id,approvalId,allow}` | Снимок после решения по этому запросу разрешения |

Операция всегда имеет `id`, `tool` и `state`. Состояние `approval` добавляет `approval:{id,detail}`. В `succeeded`, `failed` и `denied` поле `content` содержит итоговые блоки MCP. Успешный `read_image` возвращает один блок изображения. Для PNG размером 4 МиБ строка JSON ответа занимает около 5,6 МБ. `running` означает, что результат ещё ожидается. `tools/call` записывает операцию перед запуском и отвечает сразу. Bridge использует стабильный `arenaCallId` для одной команды в одном разговоре. Повтор с тем же ID и аргументами возвращает сохранённый снимок. Повтор с другими аргументами отвергается.

Журнал операций действует в течение жизни дочернего процесса. После закрытия stdio сервер отзывает незавершённые разрешения и завершает сессию DSH. Если процесс потерян во время правки, Bridge должен считать исход неопределённым и сохранять запрет автоматического повтора. При перезапуске прежние идентификаторы неизвестны новому процессу. Операторские JSON-RPC методы доступны родительскому процессу через его закрытый канал и отсутствуют в `tools/list`. Bridge закрепляет происхождение пользовательской команды до вызова `arena/explicitSkill` или `arena/decide`.

## Проверка ожидания разрешения

Обычный `npm test` использует временный проект, вызывает реальный сервер и проверяет фактическое содержимое файла и вывод тестов. Для проверки ожидания дольше обычного 60-секундного запроса MCP выполните в каталоге `harness-adapter`:

```powershell
$env:ARENA_TEST_APPROVAL_DELAY_MS = '61000'
npm test
Remove-Item Env:ARENA_TEST_APPROVAL_DELAY_MS
```
